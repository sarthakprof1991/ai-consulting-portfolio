# AI Consulting Portfolio

A public, static portfolio for Sarthak Banga. It contains generalized interactive case studies on secure enterprise AI adoption, document intelligence, evaluation systems, and governed workflow automation.

## Local preview

Open `index.html` in a browser, or serve the repository root with any static HTTP server.

## Case studies

- `case-studies/ide-quality/` — Intelligent Document Extraction: a generalized case study on structured extraction, independent verification, deterministic controls, bounded recovery, escalation, and human review.
- `case-studies/governed-ai-exchange/`: Governed AI-to-Client Delivery. Reusable capability, internal review, and controlled external distribution.
- `case-studies/microsoft-365-ai-integration/`: AI Integration for Microsoft 365. Identity-aware discovery, supported retrieval, and separate action capabilities. Recommended workflow safeguards are explicitly distinguished from connector-enforced behavior.
- `case-studies/bounded-ai-remediation/`: Bounded AI-Assisted Remediation. A guided issue-to-fix workflow with permitted-change boundaries, source-based reproduction, independent checking, and reviewable delivery. Includes two invented examples that distinguish a technical investigation from a business-schema decision.

Cases 02, 03, and 04 use native expandable sections and executive/technical workflow views. With JavaScript disabled, their executive narratives and expandable sections remain available. The remediation page's two illustrative boundary examples are also readable without JavaScript. These are explanatory case studies, not live product demonstrations, and do not connect to workplace systems.

## Site assets

Each case study has its own social preview PNG and editable SVG, with canonical and social metadata. The new pages reuse the IDE page's base case-study stylesheet, with additive styles and a shared view-switch script. The original IDE narrative and controls are unchanged.

## Interactive workflow maps

Each case study now has a distinct schematic map directly after its hero, anchored at `#interactive-flow`. The maps use `styles/workflow-map.css`, `scripts/workflow-map-data.js`, and `scripts/workflow-map.js`; no dependencies, network calls, build step, or storage are required.

- Choose a route with the native route buttons, then select any stage or use **Previous**, **Next**, **Restart**, and **Play/Pause**. Playback is opt-in and advances the illustration only, never a live process. The end of each route is explicit.
- Visited connectors are teal; dashed connectors are upcoming on the selected route. Other routes remain legible. Current and visited stages also have text labels, and decisions or recommended safeguards have amber boundaries. Expand **Read the selected route** for an ordered text equivalent, including repeated stages in loops.
- Stage buttons support Tab, Enter, and Space, with `aria-pressed`, `aria-current`, and visible focus. Selecting a node outside the current route switches to a route containing it; the route selector and description update together. Repeated nodes retain their current occurrence or select their next occurrence.
- The light inspector reuses the existing approved stage prose. Its local Executive/Technical switches use `data-map-view`, not the original `data-view`; changing the inspector view preserves the selected route and stage and pauses playback to allow reading.
- **Read full stage** selects the matching original narrative view, opens the corresponding original accordion, and focuses its button or summary. IDE continues to use its original generated `.stage-button` mechanism; the other cases retain native `details`.
- On small screens, nodes become a legible vertical map with connector lanes outside the buttons. Tapping a node brings its inspector into view. **Jump to stage inspector** and **Back to selected node** provide explicit navigation without a sticky overlay.
- Manual selection, route changes, narrative navigation, and a hidden tab stop playback. Reduced-motion preferences disable timed playback and smooth map scrolling; Previous and Next remain available. `ResizeObserver` redraws the decorative, `aria-hidden` canvas from actual button geometry, including when text or viewport sizes change.
- Without JavaScript, no map controls are rendered. A brief fallback links to the existing narrative. The IDE page additionally offers verbatim executive stage passages as a no-JavaScript fallback; the other native accordions and both invented remediation boundary examples remain usable.

Routes are explanatory rather than product guarantees. The Microsoft 365 map prominently labels review and clarification as recommended workflow safeguards, not universally connector-enforced behavior. Delivery keeps human release responsibility and reusable-capability contribution distinct. IDE recovery is one bounded illustrative pass, and remediation ends at a reviewable proposal or a visible decision boundary, never direct production deployment.

### IDE-only immersive 3D scene

The IDE page progressively enhances its existing map with a real WebGL miniature document-quality world. `scripts/ide-workflow-scene-loader.js`, `scripts/ide-workflow-scene.js`, and `styles/ide-workflow-scene.css` are loaded only by `case-studies/ide-quality/index.html`. The shared renderer contains an opt-in event bridge and configurable 3D playback dwell, gated by **both** `data-workflow-map="ide"` and `data-ide-scene`. No other case-study layout or behavior is enhanced.

- **Content and state:** The same seven nodes, seven directed edges, three route descriptions/endings, approved stage prose, and source-stage handoffs remain owned by `workflow-map.js` and the unchanged data. The scene adds raised platforms, document stacks, structured record cells, an independent evidence lens/check, deterministic balance controls, a targeted correction/recovery arrow, a human-review desk, and a reviewable output tray. These are generalized procedural geometry, not workplace assets.
- **Display modes:** Desktop viewports of 900 CSS pixels or more default to 3D. Smaller viewports and forced-colors mode default to the original 2D map, with an explicit 3D opt-in. No Three.js module is loaded on that default 2D path. The persistent **3D scene / 2D map** switch preserves route, occurrence, node, inspector detail level, and camera settings; a switch pauses playback and settles scene motion. Explicit display choices last for this page visit only; there is no storage dependency.
- **Cinematic composition:** The default 3D composition is **Focus stage**: a genuine perspective close-up with the selected platform raised into the foreground, a readable HTML title, and the remaining stations receding into a darker atmospheric world. **Overview** pulls back to show all seven stages and their actual directed rails. Both modes keep an always-visible, native seven-stage navigation strip above the canvas. On narrow screens the strip scrolls horizontally inside its own container; it never expands the page. Overview uses small noninteractive numbers tied to the strip; focus does not carry overlapping background labels. Interactive targets remain at least 44 pixels; strip labels are 13 pixels, stage titles 24–32 pixels. The canvas is 560 pixels tall on desktop and 440 on smaller viewports.
- **Inspector and walkthrough:** In 3D only, the original inspector sits below the full-width scene in a two-column desktop arrangement. Its Executive/Technical state remains independent of the original narrative. Mirrored **Previous / Next / Restart / Play-Pause** controls sit immediately above the scene, beside route/step/node status, so users can watch handoffs without scrolling to the inspector. These dispatch to the original state machine; there is no second route state or timer. The IDE root's `data-scene-dwell="7500"` gives the existing scheduler a 7,500 ms dwell only while this opt-in map is in 3D, accommodating 1,500 ms of camera movement plus a 4,800 ms demonstration. The IDE 2D map and all other cases retain 4,200 ms. The optional dwell is clamped to 4,200–12,000 ms. The original live-region status, route reading list, terminal copy, and **Read full stage / Back to selected node** remain authoritative and intact.
- **Camera:** True `PerspectiveCamera`, vertical FOV 40°, clipping 0.1–150. Focus home is azimuth 30°, elevation 24°, distance `max(10.8, 8.7 / aspect)`, aimed at the selected stage at height 4.4 (4.85 on narrow compositions); the wide-screen target shifts 1.25 units left to reserve title space. Overview home is azimuth 12°, elevation 55°, distance `max(32, 29 / aspect)`, looking at the entire board. Manual offsets have bounds yaw −32° to +32°, elevation −10° to +14°, zoom 0.88–1.12; overview applies 45% of the yaw and 50% of the elevation offset. Rotate buttons move 8°, zoom buttons 0.06; Reset restores zero offsets and zoom 1 within the current composition. Mouse/pen drag uses −0.12° horizontal yaw and +0.035° vertical elevation per CSS pixel. Touch scrolling/pinch zoom remain browser-owned; no wheel listener, auto-orbit, or autonomous bobbing.
- **Stage choreography:** Selection/occurrence changes in focus mode run one interruptible 1,500 ms cubic ease-in/out transition. The camera pans to the selected stage, temporarily dollies back by up to 4.8 units, lowers its aim by up to 0.65 units to protect the tilted platform's framing, sweeps 38° in the travel direction, and rises up to 8° before closing in. The selected platform lifts to 2.65 units, scales to 1.36, and counter-rotates against the orbit with a 0.96-radian turn, 0.16-radian pitch and 0.10-radian roll pulse. A sine envelope adds up to 0.68 units of rise and 0.08 scale during the move, returning exactly to the final pose. Final stage yaw varies from 2° to 18° by object; final pitch is −0.055 radians. Background stages settle at scale 0.82 and object-color exposure 0.36. Previous reverses the choreography direction; rapid inputs sample the current rendered transforms/pose before beginning a new transition. Overview retains all seven at scale 1, with a 0.4-unit selected rise and 32% of the sweep. Switching Overview/Focus also uses the finite transition; camera buttons use a gentler 600 ms move. Manual offset bounds do not constrain the finite cinematic arc.
- **Directed handoffs and state:** The original playback scheduler and route occurrence logic remain the state owner, with only the IDE 3D dwell described above. A document packet travels for 1,200 ms only along an actual directed rail on one-step forward advancement of the same route. No reverse rail is invented for Previous, and no shortcut is invented for arbitrary selection. Packet travel is easiest to see in Overview; focus does not fabricate a connection between elevated foreground objects. Recovery still uses the right-hand `recovery → verify` rail. Switching 2D, pausing playback, changing inspector detail, reduced motion, hidden tabs, and offscreen rendering settle the latest selected pose and demonstration instead of leaving unfinished motion. The 3D picker stays with the scene even on mobile; explicit inspector/full-stage links retain navigation handoffs. The original 2D mobile selection behavior is unchanged.
- **Descriptive stage examples:** After the camera settles, focus plays a finite three-phase **Input / Action / Output** demonstration: 1,600 ms per phase, 4,800 ms total, driven by the existing demand-render loop rather than another route timer. **Replay stage** pauses route playback and replays only the current demonstration. The three native phase buttons pause and show that phase's explanatory endpoint for inspection. A visible progress line and polite action caption track the phases. Overview retains the original miniature objects and directed rails; focus replaces only the selected object's illustration with actual moving documents, field tiles, evidence links, controls and packets. Values are drawn on their 3D faces with locally generated canvas text textures; two object-local HTML labels stay readable and resolve horizontal collisions independently of perspective. No downloaded imagery, proprietary values, or performance claims are involved.
- **Example semantics:** The all-screen note is **“Invented example · explains this stage, not the selected route’s outcome.”** These are educational stage demonstrations, never another route execution model. Contract assembles required numeric A/B/Total fields and a total-control rule. Extraction moves invented A 100, B 50 and total 160 from source to record. Verification links A 100 to supporting evidence while the unclear total remains unresolved. Reconciliation visibly combines 100 and 50 into 150, compares against 160, tilts the balance, and flags a difference of 10. Recovery leaves A/B fixed, isolates only the total and sends **150 ?** to re-check—not acceptance. Escalation moves the unresolved evidence packet to a visible reviewer and waits for a decision. Output bundles separately readable **Record / Evidence / Quality state** layers, retaining a generic **Review state** tag instead of asserting an open exception or universal correctness for every selected route. The original case-study paragraphs and route descriptions/endings are untouched.
- **Reduced motion:** Focus and Overview retain instant, static perspective poses and raised selected geometry, but there is no timed spin, pop, camera travel, packet or object-demo animation. The selected demonstration starts at its explanatory Output endpoint; Input and Action remain available as instant static snapshots. Replay is disabled and labeled **Static example**. Manual camera controls and stage selection remain available; both timed-Play copies retain the original disabled state.
- **Rendering budget:** Rendering is demand-driven, with no idle animation loop. The live-bounds `syncVisibility()` fix remains: IntersectionObserver, resize, and passive scroll recalculate the current frame rectangle rather than trusting stale observer entries. RAF stops offscreen, on a hidden tab, and in 2D; skipped transitions/demonstrations settle rather than replaying on return. The first visible activation starts the initial example once. The original guided walkthrough remains the state owner offscreen. Pixel ratio is capped at 1.5 and canvas size at approximately 2.2 million pixels. Directional/rim lighting, a focused spotlight, distance fog, and one 1,024-pixel shadow map reveal depth. Text textures are generated locally at 512×160 and shared by identical strings; there are no remote textures or post-processing passes.
- **Progressive fallback:** The original map is retained until the module successfully renders a test frame. A blocked stylesheet leaves the original map entirely alone. Blocked module loads, WebGL initialization/shader failures, a 12-second loading timeout, or context loss restore the complete 2D map and disable the unavailable 3D choice for that visit. No-JavaScript narrative fallbacks are unchanged. Use an HTTP static server to test modules; opening local HTML directly may intentionally fall back to 2D.
- **Vendoring:** Three.js **0.170.0 / r170**, unmodified `three.module.min.js` (691,648 bytes), is stored at `assets/vendor/three-0.170.0/`. Its complete MIT license is included as `LICENSE` beside the module. The package was acquired as `three@0.170.0`; there is no CDN, runtime network dependency, package installation, bundler, or build step required for GitHub Pages.

#### IDE bridge and diagnostic hooks

All bridge events are dispatched/listened on the IDE map root and do not bubble:

- `workflowmap:change` emits `{ map: 'ide', node, route, step, view, playing }` after the original state renderer finishes.
- `workflowmap:request` accepts `{ action: 'snapshot' }`, `{ action: 'pause' }`, `{ action: 'redraw' }`, `{ action: 'select', node, focusInspector }`, or `{ action: 'walkthrough', command }` where command is `previous`, `next`, `restart`, or `play`. Node IDs and commands are validated by the existing renderer. Selection does not click or focus hidden 2D controls.
- Cancelable `workflowmap:locate` carries `{ node }`; the 3D handler focuses the always-visible stage strip instead of a hidden original map button.

Scene selectors: `[data-scene-mount]`, `[data-scene-frame]`, `[data-scene-canvas]`, `[data-scene-mode-button="3d|2d"]`, `[data-scene-view="overview|focus"]`, `[data-scene-focus-title]`, `[data-scene-node]`, `[data-scene-picker]`, `[data-scene-camera="left|right|in|out|reset"]`, `[data-scene-action="previous|next|restart|play"]`, and `[data-scene-status-text]`. Scope stage-button automation to `.ide-scene-picker [data-scene-node]`; historical hidden overlay buttons remain only as noninteractive overview-number anchors.

The root exposes `data-scene-mode`, `data-scene-status`, `data-scene-node`, `data-scene-active`, `data-scene-animating`, `data-scene-packet`, `data-scene-handoff`, `data-scene-labels`, `data-scene-camera-yaw`, `data-scene-camera-elevation`, `data-scene-camera-zoom`, `data-scene-render-count`, and `data-scene-reduced-motion`. Read-only `root.ideSceneDiagnostics` returns a frozen snapshot with the original route/step/view, camera/bounds, animation timings, current packet edge/progress, render count, draw calls, and pixel ratio. Wait for `data-scene-active="true"` and at least one frame after scrolling into view before taking a screenshot; initialization itself may happen offscreen.

Cinematic diagnostics add `data-scene-focus-mode`, `data-scene-transition-progress`, and `data-scene-transition-direction`. `ideSceneDiagnostics` additionally returns `cameraType`, `focusMode`, `cameraPosition`, `cameraTarget`, `cameraPose` (radius/azimuth/elevation/focus/FOV), `stageTransforms` keyed by all seven IDs (position/rotation/scale/exposure), `transitionProgress`, and `transitionDirection`. Arrays and nested snapshots are frozen. Camera yaw/elevation root attributes are the bounded manual offsets; `cameraPose` includes the temporary cinematic arc.

Descriptive-example selectors: `[data-scene-demo-replay]`, `[data-scene-demo-phase="0|1|2"]`, `[data-scene-demo-caption]`, `.ide-demo-eyebrow`, and `.ide-demo-object-label:not([hidden])`. New root attributes are `data-scene-demo-node`, `data-scene-demo-phase` (`input|action|output`), `data-scene-demo-progress` (0–1), and `data-scene-demo-status` (`waiting|running|complete|static|inspecting`). The frozen diagnostics also expose `demoNode`, `demoPhase`, `demoPhaseIndex`, `demoProgress`, `demoStatus`, `demoPending`, `demoActive`, and frozen `demoObjectPositions` arrays keyed by stage. `animationActive` includes the finite demonstration, not just camera/edge movement. `timing.demo` is 4800; `timing.demoPhase` is 1600. A stage move takes approximately 1,500 ms before demonstration progress starts; a replay starts immediately. Representative demo-only samples are 800 ms (Input), 2,400 ms (Action), 4,000 ms (Output), and 4,900 ms (complete/idle). Scene CSS/loader/module and the IDE's shared-script reference use cache token `descriptive-1`. The pinned Three.js module/license, workflow data, and other cases are unchanged.

## Publishing guardrails

This repository is public. Do not add confidential or proprietary content, including:

- Employer/client names, branding, property information, tenant data, deal data, documents, screenshots, user information, or internal URLs.
- Internal repositories, source code, prompts, model identifiers, configuration, architecture topology, security controls, API schemas/endpoints, credentials, logs, or deployment details.

Keep all case studies generalized, accurate, and approved for external publication. Use the footer confidentiality statement when sharing a case study externally.
